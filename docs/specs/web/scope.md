# スコープ

公式サイトでやること・やらないことを定義します。

## 方針

対象は「アプリを知らない人への紹介」と「最新イメージの入手」の 2 点に絞ります。ドキュメント サイト (使い方の詳細、仕様書の公開) は作りません。仕様書は引き続きリポジトリーの `docs/` で管理し、サイトからは GitHub へリンクします。

サイトの内容はリリースのたびに陳腐化しやすい (バージョン番号、アセット名、画面の見た目) ため、人手で更新する箇所を最小にします。バージョンとアセットは GitHub REST API から自動で取り込み、スクリーンショットはデモ モードで再撮影できる手順にします。

## やること

### ページ

- トップ ページ: アプリの概要、主な機能、代表的な画面のスクリーンショット ([トップ ページ](features/top-page.md))
- ダウンロード ページ: 最新バージョンのイメージをプラットフォーム別に提示し、インストール時の注意 (未署名バイナリー) を案内する ([ダウンロード ページ](features/download-page.md))
- 404 ページ

### 外観

- 固定ヘッダー (ページ リンク、言語切り替え、テーマ切り替え、GitHub リンク)、コンテンツ、フッターの 3 領域 ([ページ構成](features/pages.md))。言語とテーマの切り替えはどの画面幅でもヘッダーに常時表示する
- アプリの配色トークンをコピーしたダーク / ライト テーマ。既定は OS の設定に従い、切り替えはブラウザーに保存する ([テーマとスタイル](architecture/theme.md))
- メニューとボタンの hover にアプリと同じ glow 効果

### 多言語

- 英語を既定とし、日本語へ切り替えられる ([多言語対応](architecture/i18n.md))

### 技術基盤

- 現在のリポジトリーの `web/` に Astro で構築し、pnpm workspace のパッケージとして扱う ([リポジトリー構成](architecture/repository.md)、[技術選定](architecture/tech-stack.md))
- GitHub Actions で GitHub Pages へ公開する。main への push とリリース完了の両方で公開する ([デプロイ](architecture/deploy.md))
- スクリーンショットはデモ モードで撮影し、ファイル パスなどの個人情報をマスクする ([スクリーンショット](features/screenshots.md))

## やらないこと

| 項目 | 備考 |
| --- | --- |
| ドキュメント サイト (使い方、仕様書の公開) | 仕様書は `docs/` のまま。必要になれば Astro の Starlight などを `web/` に追加できる |
| 過去バージョンのダウンロード一覧 | ダウンロード ページは最新だけ。過去は GitHub Releases へリンクする |
| 自動更新 (アプリ内アップデート) | サイトの範囲外。アプリ側で electron-updater を導入する場合に GitHub Releases をそのまま使える |
| 独自ドメイン | `akabekobeko.github.io/parade/` で開始する。独自ドメインは `base` の削除と `CNAME` の追加だけで移行できる |
| ブログ、お知らせ | リリースの告知は GitHub Releases の Release Notes で足りる |
| Windows / Linux のスクリーンショット | macOS だけ撮影する。Windows / Linux はウィンドウ枠が違うだけで内容は同じ |
| 日本語 UI のスクリーンショット | 英語 UI だけ撮影し、両言語のページで共有する。日本語対応は設定ページの紹介と文章で明記する |
| MusicBrainz 取得画面のスクリーンショット | デモ用データが架空で結果を再現できない。文章で説明し、フッターに利用サービスとして併記する |
| 訪問者の言語による自動リダイレクト | GitHub Pages は静的ホスティングのためサーバー側で判定できない。クライアント側のリダイレクトは検索エンジンとの相性が悪いので行わない |
| アクセス解析 | 無償運用の範囲で導入しない。GitHub の Insights (Traffic) で足りる |
| コード署名 | サイトの範囲外。未署名であることと回避手順をダウンロード ページで案内する |

## 非機能要件

- JavaScript を無効にしても内容 (機能紹介、ダウンロード リンク) が読めること。テーマ切り替えと言語切り替えのリンクは JavaScript なしでも動く構造にする
- ダウンロード リンクはビルド時に静的 HTML へ埋め込み、閲覧時に GitHub REST API を呼ばないこと (未認証の API は IP あたり 60 回 / 時の制限があり、閲覧者の環境に依存する)
- スクリーンショットは Retina (2x) で撮影し、Astro の画像最適化で配信サイズを抑える。トップ ページの転送量は 3 MB 以内を目安にする
- Lighthouse (モバイル) の Performance / Accessibility / SEO を 90 以上にする
- 公開 URL とページの構成を変えない限り、リリースのたびに人手で編集するファイルがないこと
