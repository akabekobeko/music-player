# v1.1 スコープ

v1.1 でやること・やらないことを定義します。

## 方針

v1.0 のスコープで「メタデータの編集は読み取りのみ。編集は別途検討」としていた項目を実装します。ライブラリーの正はあくまで音楽ファイルであり、DB はそのキャッシュです。編集はファイルへ書き込み、その結果を DB へ取り込み直す一方向の流れにします (インポートと同じ経路を通す)。

## v1.1 でやること

### 曲情報の編集

- 曲情報ダイアログの Details タブを編集可能にする ([曲情報ダイアログの編集](features/music-info-dialog.md))
- 適用ボタンの追加。初期状態は非活性、初期状態に対して変更があれば活性化
- 項目ごとの validation ([編集項目と validation](features/music-info-fields.md))
- アートワークの差し替え・削除 ([アートワークの編集](features/artwork-edit.md))

### 複数選択の編集

- 複数の曲を選択した状態で曲情報ダイアログを開き、合成した情報を表示・編集する ([複数選択の編集](features/multi-edit.md))
- 曲リストの複数選択を Album / Playlist ビューへも展開する ([曲リストの複数選択](features/selection.md))

### 適用と反映

- @akabeko/music-metadata-editor による音楽ファイルへの書き込み ([メタデータの書き込み](architecture/metadata-write.md))
- Artists / Albums / Playlists 各ビューとカレントキューへの即時反映 ([ライブラリーへの即時反映](features/library-refresh.md))

### 技術基盤

- form 編集と validation の管理ライブラリーとして TanStack Form + zod を導入 ([form ライブラリー選定](architecture/form-library.md))

## v1.1 でやらないこと

| 機能 | 備考 |
| --- | --- |
| ファイルの移動・リネーム | Apple Music はアルバム アーティストやアルバム名の変更でディレクトリーを移動するが、ユーザーのファイル運用が不明なため Parade は行わない。対応するとしても将来バージョン |
| フロントカバー以外の画像 | 裏ジャケットなど `CoverFront` 以外の埋め込み画像はファイルに保持するが、UI では扱わない |
| 歌詞・チャプターの編集 | DB に取り込んでいない (v1.0 の方針を継続) |
| DB にない項目の編集 | comment / copyright / trackTotal / discTotal など。ファイルの値は書き込み時に保持する |
| 編集破棄の確認ダイアログ | 未適用のままダイアログを閉じると変更は破棄される。要望次第で v1.x |
| 外部での変更検知 | 他アプリでタグを変更した場合は再インポートで取り込む (v1.0 と同じ) |
| 再生中の曲の無停止編集 | 対象に現在曲が含まれる場合は停止してから適用する ([適用処理](features/apply-flow.md)) |

## 非機能要件

- 書き込み中に元ファイルが壊れないこと (一時ファイルへ書き出してから置き換える)
- 1 件の失敗が残りの曲の適用を止めないこと (インポートと同じ per-item 集約)
- DB スキーマの変更なし。編集対象はすべて `musics` テーブルの既存列
