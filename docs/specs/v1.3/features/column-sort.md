# ソート

カラムのヘッダーをクリックして、昇順・降順を切り替えます。

## 操作

- ソートできるカラム ([カラム定義](columns.md)) のヘッダーは、表示名を含む `<button>` です
- ソート中でないカラムをクリックすると、そのカラムの**昇順**でソートします
- ソート中のカラムをクリックすると、昇順と降順が入れ替わります
- ソート中のカラムは表示名の横に矢印 (昇順 `ChevronUp`、降順 `ChevronDown`) を出し、`aria-sort` を付けます
- ソート キーは常に 1 つです

## 登録順へ戻す

プレイリストを開いた直後は登録順 (`ordinal` の昇順) です。ソートを解除する専用の操作は設けず、**連番カラム (`#`) のヘッダーをクリックすると登録順へ戻ります。** 「ソートなし」という第 3 の状態を作らないため、クリックは常に 2 状態の切り替えで済みます。

- 静的プレイリストの登録順は `playlist_musics.position` の順です
- 動的プレイリストの登録順はルールの評価結果の順です (ルールの `sort` や `limit` を適用済み)。`random` の場合は評価のたびに変わります

## 状態

- ソートの状態 (`PlaylistSort`) は `PlaylistContent` の `useState` に持ちます。保存しません
- `PlaylistContent` はプレイリストごとに再マウントされるため (`key`)、別のプレイリストを開くと登録順へ戻ります
- ソート中のカラムをカラム メニューで非表示にしたときは、登録順へ戻します。`PlaylistContent` がレンダー中に「ソート キーが表示中のカラムにない」ことを検出し、その場で state を `DEFAULT_PLAYLIST_SORT` へ書き換えます (React の「props の変化に応じた state の調整」の書き方。useEffect は使わない)
- state を書き換えるため、非表示にしたカラムを再び表示してもソートは復活しません
- ソートを参照する処理 (表示順、矢印、Drag & Drop の可否) は、すべてこの state を使います

## 比較規則

比較は純関数 `comparePlaylistRows(sort)` にまとめます。

| カラム | 比較 |
| --- | --- |
| `ordinal` | 位置の数値 |
| `title` / `artist` / `album` / `albumArtist` | `compareNameWithoutArticle` (冠詞を除き、大文字と小文字を区別しない。Artists ビューと同じ) |
| `genre` / `composer` / `lyricist` / `producer` / `conductor` / `publisher` / `audioFormat` | 大文字と小文字を区別しない文字列比較 |
| `year` / `track` / `disc` / `bpm` / `rating` / `duration` | 数値 |
| `addedAt` | ISO-8601 文字列の比較 (日時順と一致する) |

- **値のない行は向きにかかわらず末尾**へ置きます。降順にしたとき、値のない行が先頭を埋めないようにするためです。「値のない」の定義は下の表のとおりで、セルが空欄になる条件 ([カラム定義](columns.md)) と一致します
- **同値は登録順の昇順**で並べます。降順でも同値の中は登録順のままです。アルバムでソートしたときに、プレイリストへ入れた順が保たれます
- 表示は日付のみの `addedAt` も、比較は秒まで含む元の値で行います

| カラム | 値のない条件 |
| --- | --- |
| タグの文字列のカラム (`title` から `publisher` まで) | 空文字 |
| `year` / `bpm` / `rating` | `null`。0 は値として扱う (`rating` の 0 は星 0 個) |
| `track` | 0 (タグなしを 0 で保存しているため) |
| `ordinal` / `disc` / `duration` / `audioFormat` / `addedAt` | なし。常に値を持つ |

`disc` はタグがなくても 1 で保存されるため、タグなしの曲は 1 として並びます。`duration` の 0 (計測できなかった曲) は値として扱い、昇順の先頭に並びます。

## 他の機能との関係

| 機能 | ソート中の挙動 |
| --- | --- |
| 連番の表示 | 登録順の番号のまま。表示順に振り直さない |
| 曲の絞り込み | 絞り込んだ結果をソートする。どちらを先に操作しても結果は同じ |
| 再生 | 表示中の順序でキューを作る ([Playlists のテーブル](playlist-table.md)) |
| 選択 | 保たれる。単位が位置なので、表示順が変わっても同じ行を指す |
| Drag & Drop での並べ替え | 登録順の昇順のときだけ有効 |
| 行の削除 (プレイリストから外す) | 有効。位置を指定して外すため、表示順に依存しない |
| 再生中のキュー | 変わらない。ソートは表示の変更で、次に再生を始めたときのキューに反映される |

## 処理の位置

絞り込みと同じくレンダー中に導出します (`musics` → 位置を付ける → 絞り込み → ソート)。1 万曲のソートは数ミリ秒から十数ミリ秒で終わる見込みですが、再生時間の更新などで `PlaylistContent` が頻繁に再レンダーされる場合は計測し、問題があれば導出の位置を見直します ([状態管理](../../v1.0/renderer/state-management.md) の方針どおり、計測してから対処する)。
