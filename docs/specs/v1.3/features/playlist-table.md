# Playlists のテーブル

Playlists ビューのコンテンツ領域 (`/playlists/p<id>`、`/playlists/s<id>`) の曲リストをテーブルにします。v1.0 の [Playlist](../../v1.0/features/playlist.md) の「表示」を置き換える仕様です。

## 画面の構成

```
┌ コンテンツ ツールバー ──────────────── [カラム メニュー] [曲の絞り込み] ┐
├ PlaylistHeader   名前 / 曲数 / 総時間 / Play / Shuffle / メニュー ─────┤
├ ヘッダー行 (固定)   #   Title ▲       Artist      Album      Time      ┤
│ 行                  1   ...           ...         ...        3:45  [⋯] │
│ 行                  2   ...           ...         ...        4:10  [⋯] │
└──────────────────────────────────────────────────────────────────────┘
```

- `PlaylistHeader` は v1.2 のまま変えません
- ヘッダー行はスクロールしても上端へ固定します ([テーブルの構造](../architecture/table-structure.md))
- 静的プレイリストと動的プレイリストで同じテーブルを使います

## v1.2 からの変更点

| 項目 | v1.2 | v1.3 |
| --- | --- | --- |
| 要素 | `<ul>` + `MusicRow` | `<table>` + `PlaylistTableRow` |
| ヘッダー行 | なし | あり (固定) |
| カラム | 連番、タイトル、アーティスト、アルバム、時間の固定 | [カラム定義](columns.md) から選択 |
| カラム幅 | アーティストとアルバムは各 1/4、タイトルは残り | px で指定し、リサイズできる ([カラム幅のリサイズ](column-resize.md)) |
| 並び | 登録順のみ | ヘッダーのクリックでソート ([ソート](column-sort.md)) |
| 横スクロール | なし | カラム幅の合計がコンテナーを超えると発生 |

## 行の操作

v1.2 の挙動を保ちます。

| 操作 | 挙動 |
| --- | --- |
| 行のクリック | 選択。Shift で範囲、Cmd / Ctrl でトグル ([曲リストの複数選択](../../v1.1/features/selection.md)) |
| 行のダブルクリック | その曲から再生 |
| 先頭セル (連番) のホバー | 再生ボタン。再生中・一時停止中の行は一時停止・再開ボタン |
| [⋯] と右クリック | 曲メニュー。項目と対象の判定 (`menuTargetsOf`) は v1.2 と同じ |
| 行の Drag & Drop | 静的プレイリストの並べ替え。条件は下記 |

- クリックの対象は行全体です。セルごとの選択やフォーカスは持ちません
- 選択の単位は v1.1 と同じく位置 (`position`) です。ソートで表示順が変わっても選択は保たれ、Shift での範囲選択は表示中の順序で行います
- 再生のキューは表示中の順序 (絞り込みとソートの適用後) で作ります。表示と再生の順序が一致します

## 並べ替えの条件

Drag & Drop での並べ替えは、表示順が登録順と一致するときだけ有効にします。

- 静的プレイリストである
- 曲の絞り込みが空である
- ソートの state が登録順の昇順 (`DEFAULT_PLAYLIST_SORT`) である ([ソート](column-sort.md) の状態)

条件を満たさないときは行を `draggable` にしません。ソート中に並べ替えると「どの位置へ入ったか」が表示と一致しないためです。

## 空の状態と失敗

- 読み込みの失敗とプレイリストが空のときの文言は v1.2 のまま、ヘッダー行の上に表示します
- 曲が 0 件でもヘッダー行は表示します。絞り込みで 0 件になったときに、カラムの操作を続けられるようにするためです
