# v1.3 スコープ

v1.3 でやること・やらないことを定義します。

## 方針

対象は Playlists ビューのコンテンツ領域だけです。プレイリストは異なるアーティスト・アルバムの曲が混在するため、カラムで見比べてソートする利点が最も大きいビューです。Artists / Albums ビューの曲リストは v1.2 のまま変えません。

行の操作 (選択、再生、メニュー、Drag & Drop での並べ替え) は v1.2 の挙動を維持し、見た目と列の扱いだけを変えます。変更の中心は Renderer です。Main プロセスの変更は設定 (`settings.json`) の項目追加とその検証だけで、DB と IPC チャネルには手を入れません。

## v1.3 でやること

### テーブル表示

- 曲リストを `<table>` へ置き換え、ヘッダー行を上端へ固定する ([テーブルの構造](architecture/table-structure.md))
- 表示できるカラムを増やす。v1.2 の連番・タイトル・アーティスト・アルバム・時間に加え、アルバム アーティスト、ジャンル、年などを選べる ([カラム定義](features/columns.md))
- 行の Virtualization を維持する

### カラムの操作

- ヘッダーの境界をドラッグして幅を変える ([カラム幅のリサイズ](features/column-resize.md))
- ヘッダーをクリックして昇順・降順を切り替える ([ソート](features/column-sort.md))
- コンテンツ ツールバーのメニュー ボタンで表示するカラムを切り替える ([表示カラムの切り替え](features/column-visibility.md))
- ヘッダーをドラッグ & ドロップしてカラムの並び順を変える ([カラムの並べ替え](features/column-reorder.md))

### 技術基盤

- カラムの表示、並び順、幅を `AppSettings` へ保存し、次回起動時に復元する ([カラム設定の永続化](architecture/column-settings.md))
- テーブルは独自実装とし、ライブラリーを追加しない ([テーブル ライブラリー選定](architecture/table-library.md))

## v1.3 でやらないこと

| 機能 | 備考 |
| --- | --- |
| Artists / Albums ビューのテーブル化 | アルバム単位でまとまった曲リストはカラムを増やす利点が小さい。Playlists の結果をみて v1.x で検討 |
| セルの編集 | 曲情報の編集は曲情報ダイアログ (v1.1) で行う。テーブルは表示専用 |
| ソートの永続化 | ソートはプレイリストを開いている間だけの表示状態。プレイリストを切り替えると登録順へ戻る |
| ソート結果を登録順として保存 | 静的プレイリストの並び (`position`) はソートで書き換えない。保存する操作は v1.x で検討 |
| 複数カラムでのソート | ソート キーは 1 つ。同値は登録順で安定させる |
| プレイリストごとのカラム設定 | カラムの表示と幅は全プレイリスト共通 |
| キーボードでのリサイズ | ポインター操作のみ。ソートはヘッダーが `<button>` なので Enter / Space でも切り替えられる (v1.3 の範囲内) |
| 行の高さの変更 | `MUSIC_ROW_HEIGHT` (36px) 固定のまま |

## 非機能要件

- 1 万曲のプレイリストでも、スクロールとソートの切り替えで体感できる引っかかりがないこと (Virtualization を維持し、ソートは表示中のプレイリストにだけ行う)
- リサイズのドラッグ中は設定を保存せず、ドラッグの終了時に 1 回だけ保存すること
- 壊れた設定値で表示が崩れないこと。未知のカラム id と、数値でない幅・0 以下の幅は捨てて既定値を使い、最小幅を下回る幅は最小幅へ切り上げる
- DB スキーマと IPC チャネルの変更なし (Main の変更は `AppSettings` の項目追加と sanitize のみ)
