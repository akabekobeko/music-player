# テーブル ライブラリー選定

Playlists のテーブルを組み立てる方法の選定です。候補の比較は [候補の比較](table-library-candidates.md) にまとめています。

## 結論

**独自実装とし、テーブル用のライブラリーは追加しません。** 行の Virtualization は v1.0 から使っている @tanstack/react-virtual を継続します。

## 要件

1. **ヘッダーの固定、リサイズ、ソート、表示の切り替え**ができること
2. **行の Virtualization を維持**できること
3. **既存の行操作を保てる**こと。位置 (`position`) を単位とする複数選択、Drag & Drop での並べ替え、[⋯] と右クリックのメニュー、再生中の行の glow ([Playlists のテーブル](../features/playlist-table.md))
4. **状態の置き場所を自分で決められる**こと。カラムの表示と幅は React の外の store に置き、`AppSettings` へ保存する ([カラム設定の永続化](column-settings.md))
5. v1.0 の [状態管理](../../v1.0/renderer/state-management.md) の方針 (useMemo / useCallback を既定にしない、派生値はレンダー中に計算する) に合うこと

## 独自実装を選ぶ理由

- **必要な機能が小さい**: グループ化、集計、ページング、カラム フィルター、行の展開はいずれも使いません。残る 3 つの機能は、それぞれ小さな純関数と hook で書けます
  - ソート: 比較関数 1 つと `toSorted`
  - 表示の切り替え: カラム定義の配列を id で絞る
  - リサイズ: ポインター イベントを追う hook 1 つ
- **先行例が同じ判断をしている**: 先行例の GUI は @tanstack/react-table を依存に持ちますが、スプレッドシートはそれを使わず `<table>` と @tanstack/react-virtual で実装しています。リサイズの hook (`useColumnResize`) と幅の解決 (`resolveColumnWidths`) はほぼそのまま移植できます
- **メモ化の方針と衝突しない**: TanStack Table は `data` と `columns` に安定した参照を求めます。Parade の曲リストは絞り込みや楽観的な並べ替えの結果をレンダー中に導出しているため、採用すると useMemo を前提にした書き方へ寄せることになります
- **行の見た目はどちらでも自前**: TanStack Table は headless で、マークアップと見た目は利用側が書きます。行の glow や連続選択の角丸の結合といった手間のかかる部分は、ライブラリーを入れても減りません

## 見直しの条件

次のいずれかを扱うことになれば、TanStack Table の採用を改めて検討します。

- カラムのグループ化やピン留め、複数カラムでのソートなど、状態の組み合わせが増える機能
- Artists / Albums を含む複数のビューで、異なるカラム構成のテーブルを共有する場合

独自実装でも、カラム定義・ソート・幅の解決は純関数として切り出します。乗り換える場合はこれらを TanStack Table のカラム定義と状態へ対応づければよく、行コンポーネントはそのまま使えます。
