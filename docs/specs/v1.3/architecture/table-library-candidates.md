# テーブル ライブラリー候補の比較

[テーブル ライブラリー選定](table-library.md) で検討した候補の比較です。バージョンは 2026-09 時点の最新安定版です。

## 比較表

| 観点 | 独自実装 | TanStack Table 9.2 | データ グリッド製品 (AG Grid など) |
| --- | --- | --- | --- |
| 設計の中心 | カラム定義と純関数 | headless。機能を `tableFeatures` で登録し、状態から行モデルを導出 | 見た目と操作まで含む完成品 |
| 追加する依存 | なし | `@tanstack/react-table` | 製品本体 (大きい) |
| ソート | 比較関数を自作 | `rowSortingFeature` | 標準 |
| リサイズ | hook を自作 (先行例から移植) | `columnSizingFeature` / `columnResizingFeature` (状態と計算。ハンドルの描画は自前) | 標準 |
| 表示の切り替え | 配列の絞り込み | `columnVisibilityFeature` (メニューは自前) | 標準 |
| Virtualization | @tanstack/react-virtual | @tanstack/react-virtual と組み合わせる | 内蔵 |
| 行のマークアップと見た目 | 自前 | 自前 | 製品のテーマに従う |
| 状態の外部化 | 自由 | 可能 (状態を外から渡す) | 製品の API 経由 |
| メモ化の要求 | なし | `data` / `columns` は安定した参照が必要 | 製品による |

## 各候補の評価

### 独自実装

採用。理由は [テーブル ライブラリー選定](table-library.md) のとおりです。懸念は機能が増えたときの保守ですが、v1.3 の範囲では状態が「表示するカラムの id」「カラムごとの幅」「ソート キーと向き」の 3 つだけで、互いに干渉しません。

### TanStack Table

次点。form ライブラリー ([v1.1 の選定](../../v1.1/architecture/form-library.md)) や Virtualization と同じ TanStack 製で、設計の考え方も揃っています。不採用の理由は機能に対して過剰なことです。

- 得られるのはソート・幅・表示の状態管理と行モデルの導出で、いずれも自作の分量が小さい
- ヘッダーのリサイズ ハンドル、ソートの表示、カラム メニュー、行の見た目は採用しても自前で書く
- v9 は v8 から API が大きく変わっており (`useTable`、機能の明示的な登録)、学習の対象が増える
- 位置を単位とする選択と Drag & Drop での並べ替えは Parade 固有で、ライブラリーの行選択の機能とは別に持つことになる

機能が増えたときの乗り換え先として記録します。

### データ グリッド製品

不採用。見た目と操作が製品の流儀に固定され、`MusicRow` と揃えた行の見た目 (角丸、glow、連続選択の結合) を再現しにくくなります。バンドルも大きく、一部の機能は商用ライセンスが必要です。

### CSS だけで組む案 (`<table>` を使わない)

v1.2 の `<ul>` のまま、カラム幅を CSS 変数で与える案も検討しました。見た目は同じにできますが、ヘッダーとセルの対応が支援技術へ伝わりません。表形式のデータなので `<table>` の要素を使い、レイアウトだけ CSS で上書きします ([テーブルの構造](table-structure.md))。
